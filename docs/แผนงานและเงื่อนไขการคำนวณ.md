## 2. สถาปัตยกรรม (ตามที่เลือก: HTML ไฟล์เดียว + คำนวณล่วงหน้า)

```
build_dashboard.py                 (Python — รันเมื่อมีข้อมูลใหม่)
  ├─ 1. อ่าน data/*/**.xlsx ทุกไฟล์ (streaming openpyxl read_only)
  ├─ 2. เพิ่มคอลัมน์ agesurvey = ชื่อโฟลเดอร์ (3ปี/6ปี/12ปี/60ปี)
  ├─ 3. append เป็นตารางเดียว → บันทึก combined.csv (ไว้ตรวจสอบย้อนหลัง)
  ├─ 4. กรองเฉพาะ date_serv ไม่ว่าง (79,170 แถว)
  ├─ 5. join ampname/hosname จาก hospitals.csv (cp874)
  ├─ 6. คำนวณ flag ระดับบุคคล + สรุปเป็น counter ราย hoscode
  └─ 7. ฝัง JSON ลงใน dashboard.html (ไฟล์เดียว เปิดด้วยเบราว์เซอร์)

dashboard.html                     (ผลลัพธ์ — ส่งต่อ/เปิดออฟไลน์ได้)
  └─ รวม counter ราย hoscode → แสดงตารางที่ 1–7 ตามตัวกรองที่เลือก
```

**เหตุผลที่สรุปเป็น counter ราย hoscode:** ตัวกรองที่ต้องการคือ ระดับจังหวัด / อำเภอ / หน่วยบริการ ซึ่งทุกระดับรวมจาก hoscode ได้ทั้งหมด → JSON เล็ก (188 หน่วย × 4 กลุ่มวัย × ~40 ตัวเลข ≈ 200 KB) เปิดเร็ว ไม่ต้องส่งข้อมูลรายบุคคลออกไป (ปลอดภัยเรื่องข้อมูลส่วนบุคคล)

**ตัวกรองบนหน้าเว็บ:** จังหวัด → อำเภอ (ampname) → หน่วยบริการ (hoscode) แบบ cascade + ปุ่ม export ตารางเป็น Excel/CSV

## 3. Logic การคำนวณ (แปลจาก ตารางรายงานและเงื่อนไขการคำนวณ.docx)

### นิยามพื้นฐาน
- **ตรวจฟัน (examined)** = `date_serv` ไม่เป็นค่าว่าง
- **ผ่านเกณฑ์คุณภาพ (quality)** = examined **และ** `providertype ∈ (02, 06)` **และ** เงื่อนไขตามกลุ่มวัย:

| กลุ่ม | เงื่อนไข |
|---|---|
| 3 ปี | `dteeth` 1–20 **และ** `dcaries+dfilling+dextract ≤ 20` **และ** `dteeth+dextract = 20` |
| 6 ปี | `pteeth` 1–12 **และ** `pfilling+pextract+pcaries ≤ 12` **และ** `pcaries+pfilling ≤ pteeth` |
| 12 ปี | `pteeth` 1–28 **และ** `pfilling+pextract+pcaries ≤ 28` **และ** `pcaries+pfilling ≤ pteeth` |
| 60+ | `pteeth` 0–32 **และ** `permanent_permanent+permanent_prosthesis+prosthesis_prosthesis` 0–10 **และ** `pteeth+pextract > 0` |

> ทุกตารางตั้งแต่ตารางที่ 2 เป็นต้นไป ใช้ **ตัวหาร = จำนวนคนที่ผ่านเกณฑ์คุณภาพ**

### ตารางที่ 1 — คุณภาพข้อมูล
อายุ | จำนวนที่ตรวจ | จำนวนที่ผ่านเกณฑ์ | ร้อยละ (ผ่าน/ตรวจ ×100)

### ตารางที่ 2 — ร้อยละปราศจากฟันผุ / ประสบการณ์ฟันผุ
ใช้ฟันน้ำนม (d*) สำหรับอายุ 3, ฟันแท้ (p*) สำหรับ 6/12/60+

| คอลัมน์ | นับคนที่ |
|---|---|
| ปราศจากฟันผุ | `caries+filling+extract = 0` |
| ฟันผุไม่ได้รักษา | `caries > 0` |
| ฟันถอน | `extract > 0` |
| ฟันอุด | `filling > 0` |
| ฟันผุถอนอุด | `caries+filling+extract > 0` |

### ตารางที่ 3 — ค่าเฉลี่ยซี่ต่อคน
`ฟันที่มีในปาก` = mean(dteeth หรือ pteeth), `ฟันผุ` = Σcaries/N, `ฟันถอน` = Σextract/N, `ฟันอุด` = Σfilling/N, `ฟันผุถอนอุด` = ผลรวมทั้งสาม

### ตารางที่ 4 — สภาวะปริทันต์ (เฉพาะ 12 และ 60+)
สร้างคอลัมน์ `GumStatus` จากฟิลด์ `gum` 6 หลัก (sextant):

**ขั้นที่ 1 — ทำความสะอาดค่า (ตามที่ยืนยัน)**
- ค่าที่สั้นกว่า 6 หลัก → **ตีความเป็นค่าเดียวกันทั้งปาก** เช่น `"9"` → `999999`, `"0"` → `000000`, `"4"` → `444444`
- เลข `4` และ `5` → **แปลงเป็น `3` (ปริทันต์อักเสบ)** ตามรหัส CPI เดิม
- ค่าว่าง หรือค่าที่ยังไม่เข้ารูปแบบหลังทำความสะอาด → ตัดออกจากตารางที่ 4/5 และรายงานไว้ในหน้า Data Quality

**ขั้นที่ 2 — หา GumStatus**
- ถ้าทุก sextant = 9 → 9
- มิฉะนั้น → **ค่าสูงสุดของ sextant ที่มีค่า 0–3**
- แสดงเป็น: 0=ปกติ, 1=เลือดออก, 2=เหงือกอักเสบ, 3=ปริทันต์, 9=ตรวจไม่ได้ *(map ตามลำดับรหัส ตามที่ยืนยัน)*

### ตารางที่ 5 — ค่าเฉลี่ยจำนวน sextant แต่ละสภาวะ (เฉพาะ 12 และ 60+)
นับจำนวน sextant ในแต่ละรหัส (0/1/2/3/9) ต่อคน แล้วหาค่าเฉลี่ย (รวม 6 sextant ต่อคน)

### ตารางที่ 6 — ผู้สูงอายุ (เฉพาะ 60+)
- ฟันใช้งาน 20 ซี่: `pteeth ≥ 20`
- คู่สบฟันหลัง ≥ 4 คู่: `permanent_permanent+permanent_prosthesis+prosthesis_prosthesis ≥ 4`
- ทั้งสองเงื่อนไขพร้อมกัน

### ตารางที่ 7 — ความจำเป็นในการรักษา
| คอลัมน์ | เงื่อนไข |
|---|---|
| ทาฟลูออไรด์ | `need_fluoride = 1` |
| เคลือบหลุมร่องฟัน | `need_sealant > 0` |
| อุดฟัน | อายุ 3: `need_dfilling > 0` / อายุ 6,12,60+: `need_pfilling > 0` |
| ถอนฟัน/รักษารากฟัน | อายุ 3: `need_dextract > 0` / อายุ 6,12,60+: `need_pextract > 0` |
| ขูดหินปูน | `need_scaling = 1` |

## 4. ข้อตกลงการตีความ (ยืนยันแล้ว)

1. ✅ **ตารางที่ 3 เอกสารพิมพ์ผิด** — อายุ 3 ปี ระบุ "ค่าเฉลี่ยฟันถอน = dcaries" และ "ค่าเฉลี่ยฟันอุด = dcaries" (copy-paste ซ้ำ) → ใช้ `dextract` และ `dfilling`
2. ✅ **ตารางที่ 6 "PTEETH = 20"** → ตีความเป็น **≥ 20**
3. ✅ **ตารางที่ 7 เคลือบหลุมร่องฟัน** = `need_sealant > 0`
4. ✅ **ค่า gum ผิดรูปแบบ** → ค่าสั้นกว่า 6 หลักตีความเป็นค่าเดียวทั้งปาก, เลข 4/5 มองเป็น 3 (ปริทันต์) — รายละเอียดในตารางที่ 4
5. **denttype ไม่ตรงกลุ่มวัย**: เช่นในกลุ่ม 12 ปี มี denttype=2/4/5 ปะปน → แผนนี้ **ไม่ใช้ denttype กรอง** ยึดตามโฟลเดอร์ (agesurvey) อย่างเดียวตามที่สั่ง
6. คอลัมน์ `result` (ไม่ตามเกณฑ์/…) ที่มากับไฟล์ HDC จะ **ไม่นำมาใช้** เพราะเกณฑ์คุณภาพคำนวณเองตามเอกสาร

## 5. ลำดับงาน

1. `build_dashboard.py` — รวมไฟล์ + เพิ่ม agesurvey + บันทึก `combined.csv`
2. โมดูลคำนวณ flag ระดับบุคคล + unit test กับตัวอย่างที่คำนวณมือ
3. สรุปเป็น JSON counter ราย hoscode + join hospitals.csv
4. `dashboard.html` — ตัวกรอง cascade (จังหวัด/อำเภอ/หน่วยบริการ) + ตารางที่ 1–7 + กราฟ + ปุ่ม export
5. หน้า Data Quality: รายการที่ตกเกณฑ์แยกตามสาเหตุ (providertype ผิด / ฟันเกินพิสัย / gum ผิดรูปแบบ)
6. ตรวจสอบ: ยอดรวมทุกอำเภอ = ยอดจังหวัด, สุ่มตรวจ 1 หน่วยบริการเทียบกับการคำนวณตรงจาก Excel
