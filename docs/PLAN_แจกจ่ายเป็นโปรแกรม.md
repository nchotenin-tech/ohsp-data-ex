# การแจกจ่ายเป็นโปรแกรม .exe ผ่าน GitHub — สรุปสิ่งที่ทำแล้ว

สถานะ: โค้ดและระบบ build พร้อมใช้งานแล้ว เหลือขั้นตอนที่ต้องทำบนเครื่อง Windows และบัญชี GitHub ของคุณ

---

## 1. ประสบการณ์ของผู้ใช้ปลายทาง

```
1. เข้าหน้า Releases บน GitHub → ดาวน์โหลด OralHealthDashboard-v1.0.0.zip
2. คลิกขวา → Extract All  ไว้ที่ไหนก็ได้ เช่น D:\Dashboardช่องปาก\
3. ดับเบิลคลิก OralHealthDashboard.exe  (ครั้งแรก โปรแกรมสร้างโฟลเดอร์ data ให้แล้วปิด)
4. นำไฟล์ Excel จาก HDC มาวางใน data\3ปี  data\6ปี  data\12ปี  data\60ปี
5. ดับเบิลคลิกอีกครั้ง → รอ 1-3 นาที → เบราว์เซอร์เปิดรายงานขึ้นมาเอง
```

ในไฟล์ zip มีแค่ตัวโปรแกรม เอกสารประกอบ และไฟล์ `อ่านก่อนใช้งาน.txt`
ส่วนโฟลเดอร์ `data` ให้โปรแกรมสร้างเองบนเครื่องผู้ใช้ เพื่อเลี่ยงปัญหาชื่อโฟลเดอร์ภาษาไทยเพี้ยนตอนแตก zip

## 2. สิ่งที่แก้ไขในโค้ดแล้ว

| # | เรื่อง | สิ่งที่ทำ | สถานะ |
|---|---|---|---|
| 1 | ตำแหน่งไฟล์ตอนเป็น .exe | ตรวจ `sys.frozen` แล้วใช้โฟลเดอร์ของ .exe เป็นที่เก็บ data และผลลัพธ์ | ทดสอบแล้ว |
| 2 | ไฟล์ประกอบ | ฝัง `dashboard_template.html` และ `hospitals.csv` เข้าไปใน .exe และยอมให้ผู้ใช้วางไฟล์ทับข้าง ๆ .exe ได้ | ทดสอบแล้ว |
| 3 | ภาษาไทยบนหน้าจอ | ตั้ง code page 65001 และ reconfigure stdout เป็น UTF-8 | ทำแล้ว |
| 4 | หน้าต่างปิดวืบ | ดักข้อผิดพลาดทุกชนิด แสดงข้อความไทย และรอกด Enter ก่อนปิด (เฉพาะโหมด .exe) | ทดสอบแล้ว |
| 5 | ชื่อโฟลเดอร์ | อ่านชื่อโฟลเดอร์แบบยืดหยุ่น ดูแค่ตัวเลข 3 / 6 / 12 / 60 รองรับ `3ปี`, `3 ปี`, `age3`, `60+` | ทดสอบแล้ว |
| 6 | ความคืบหน้า | แสดงผลทีละไฟล์ และทุก 25,000 แถว | ทำแล้ว |
| 7 | เปิดรายงานเอง | `webbrowser.open()` เมื่อเสร็จ ปิดได้ด้วย `--no-open` | ทำแล้ว |
| 8 | ความเร็ว | เขียนไฟล์กลางลงโฟลเดอร์ temp ก่อนย้าย และเก็บวันที่ล่าสุดไว้ใน `meta.json` ลดการอ่านซ้ำหนึ่งรอบ | ข้อมูล 241,439 แถว ใช้เวลา 68 วินาที |
| 9 | ข้อมูลส่วนบุคคล | `combined.csv` ตัดคอลัมน์ name, lname, cid, addr, birth, check_vhid ออก มีตัวเลือก `--full-csv` เมื่อจำเป็น | ทำแล้ว |

## 3. การจัดการข้อผิดพลาด (ทดสอบครบทุกกรณีแล้ว)

| สถานการณ์ | พฤติกรรมของโปรแกรม |
|---|---|
| ยังไม่มีโฟลเดอร์ data | สร้างให้อัตโนมัติ พร้อมไฟล์แนะนำในแต่ละโฟลเดอร์ แล้วบอกให้นำไฟล์มาวาง |
| โฟลเดอร์ว่าง | บอกเส้นทางโฟลเดอร์ทั้งสี่ที่ต้องวางไฟล์ |
| เปิด Excel ค้างไว้ | ข้ามไฟล์ `~$...` พร้อมอธิบายว่าเกิดจากอะไร |
| หัวตารางถูกแก้ / ไม่ใช่ไฟล์ HDC | บอกชื่อไฟล์และรายชื่อคอลัมน์ที่ขาด |
| ไฟล์เสีย เปิดไม่ได้ | ข้ามเฉพาะไฟล์นั้น ทำงานต่อกับไฟล์ที่เหลือ แล้วสรุปท้ายว่าข้ามอะไรไป |
| โฟลเดอร์ชื่อไม่รู้จัก | ข้ามพร้อมบอกว่าชื่อโฟลเดอร์ต้องมีเลข 3, 6, 12 หรือ 60 |
| ไม่มีใครได้รับการตรวจ | บอกให้ตรวจสอบช่วงเวลาที่ส่งออกจาก HDC |
| เขียนไฟล์ผลลัพธ์ไม่ได้ | บอกว่าน่าจะเปิดไฟล์ค้างไว้ใน Excel หรือเบราว์เซอร์ |
| รหัสหน่วยบริการไม่มีในตาราง | จัดกลุ่ม "ไม่ทราบอำเภอ" พร้อมแจ้งจำนวน |

ทุกข้อความบันทึกลง `ผลลัพธ์\log.txt` ให้ผู้ใช้ส่งกลับมาเวลาติดปัญหา

## 4. ระบบ build

### ให้ GitHub สร้างให้อัตโนมัติ — `.github/workflows/build.yml`

```bash
git tag v1.0.0
git push origin v1.0.0
```

GitHub จะเปิดเครื่อง Windows ทำสี่ขั้นตอนคือ ติดตั้งไลบรารี สร้าง .exe ด้วย PyInstaller
ทดสอบด้วยข้อมูลจำลอง แล้วแนบไฟล์ zip ขึ้นหน้า Releases
กด Run workflow เองจากหน้า Actions ก็ได้ถ้ายังไม่อยากติด tag

### สร้างเองบนเครื่อง Windows — `build.bat`

ดับเบิลคลิก `build.bat` ได้เลย สคริปต์จะตรวจว่ามี Python ไหม ติดตั้งไลบรารีให้
สร้าง .exe แล้วประกอบ zip ให้ครบ

### การทดสอบอัตโนมัติ

`tools/make_sample_data.py` สร้างข้อมูลจำลอง 2,400 แถว (ไม่ใช่ข้อมูลจริง)
workflow จะรัน .exe กับข้อมูลชุดนี้ทุกครั้งที่ build และตรวจว่าได้ไฟล์รายงานออกมาจริง
ถ้าโค้ดพังจะรู้ทันทีก่อนปล่อยให้พื้นที่ใช้

## 5. สิ่งที่ผู้ใช้จะเจอครั้งแรก

Windows จะขึ้น **"Windows protected your PC"** เพราะไฟล์ยังไม่ได้เซ็นด้วยใบรับรองดิจิทัล
(ใบรับรอง code signing มีค่าใช้จ่ายรายปีหลักหมื่นบาท)
ผู้ใช้กด **More info → Run anyway** ครั้งแรกครั้งเดียว เขียนอธิบายไว้แล้วใน README และไฟล์ `อ่านก่อนใช้งาน.txt`

ถ้าโปรแกรมป้องกันไวรัสของบางหน่วยงานแจ้งเตือนผิดพลาดบ่อย ทางแก้คือเปลี่ยนจาก `--onefile`
เป็น `--onedir` ซึ่งโดนแจ้งเตือนน้อยกว่าและเปิดเร็วกว่า แลกกับผู้ใช้ต้องแตกทั้งโฟลเดอร์

ขนาดไฟล์ .exe ประมาณ 15–35 MB ขึ้นกับรุ่นของ Python และ Windows ที่ใช้ build

## 6. โครงสร้าง repository

```
oral-health-dashboard/
├── src/
│   ├── build_dashboard.py          โค้ดหลัก
│   ├── dashboard_template.html     แม่แบบหน้าเว็บ
│   └── hospitals.csv               ตารางหน่วยบริการทั่วประเทศ
├── tools/
│   ├── make_sample_data.py         สร้างข้อมูลจำลองสำหรับทดสอบ
│   └── make_methodology_doc.py     สร้างเอกสารอธิบายเงื่อนไขการคำนวณ
├── packaging/make_package.py       ประกอบไฟล์ zip (รองรับชื่อไฟล์ภาษาไทย)
├── docs/                           เอกสารอธิบายเงื่อนไข แผนงาน และไฟล์อ้างอิง
├── .github/workflows/build.yml     สร้าง .exe อัตโนมัติ
├── build.bat                       สร้าง .exe บนเครื่องตัวเอง
├── build_dashboard.py              ตัวเรียกใช้แบบสั้นสำหรับโหมดพัฒนา
├── .gitignore                      กันข้อมูลจริงหลุดขึ้น GitHub
└── README.md                       คู่มือภาษาไทย
```

**ข้อควรระวังที่สุด** `.gitignore` กัน `data/`, `ผลลัพธ์/`, `*.xlsx` และ `combined.csv` ไว้แล้ว
ก่อน push ครั้งแรกให้ตรวจด้วย `git status` อีกครั้งว่าไม่มีไฟล์ข้อมูลจริงติดไปด้วย

## 7. สิ่งที่เหลือให้คุณทำ

| ขั้น | สิ่งที่ต้องทำ | หมายเหตุ |
|---|---|---|
| 1 | สร้าง repository บน GitHub แล้ว push โค้ดขึ้นไป | ตรวจ `git status` ก่อน อย่าให้มีไฟล์ในโฟลเดอร์ data ติดไป |
| 2 | ทดสอบ `build.bat` บนเครื่อง Windows หนึ่งครั้ง | ยืนยันว่า .exe ทำงานได้จริงบน Windows |
| 3 | ติด tag `v1.0.0` แล้ว push | GitHub จะสร้างไฟล์แจกจ่ายให้เอง |
| 4 | ส่งลิงก์ Releases ให้พื้นที่ | พร้อมคู่มือในไฟล์ zip |

ถ้าต้องการไอคอนโปรแกรมเป็นรูปฟัน ให้เตรียมไฟล์ `.ico` มา แล้วผมเพิ่ม `--icon` ให้ทั้งใน `build.bat` และ workflow
