# Dashboard วิเคราะห์สภาวะช่องปาก (HDC Data Exchange)

โปรแกรมสำหรับหน่วยบริการและสำนักงานสาธารณสุข ใช้แปลงไฟล์ Excel ที่ส่งออกจากระบบ HDC
(Data Exchange การตรวจฟัน) ให้เป็นรายงานสรุปสภาวะช่องปากกลุ่มอายุ 3, 6, 12 ปี และ 60 ปีขึ้นไป
ตามแบบตารางที่ 1–7 ของกรมอนามัย

ทำงานบนเครื่องของท่านเองทั้งหมด ไม่มีการส่งข้อมูลออกนอกเครื่อง

---

## วิธีใช้งาน (สำหรับพื้นที่)

ตั้งแต่เวอร์ชัน 2.0.0 โปรแกรมเป็น **ไฟล์ HTML ไฟล์เดียว** เปิดด้วยเบราว์เซอร์ ไม่ต้องติดตั้ง
และไม่ถูก Windows SmartScreen / Smart App Control บล็อกเหมือนไฟล์ .exe

### 1. ดาวน์โหลด

ไปที่หน้า **Releases** ของโครงการนี้ แล้วดาวน์โหลดไฟล์ `OHSP-Dashboard-vX.Y.Z.html`
เก็บไว้ที่ไหนก็ได้ ส่งต่อทาง LINE หรืออีเมลก็ได้

### 2. ส่งออกข้อมูลจาก HDC

ส่งออกแบบ **Data Exchange** การตรวจฟัน (ไม่ใช่ปุ่มส่งออกตารางสรุป) ตามรายงานนี้

| กลุ่มอายุ | ชื่อรายงานใน HDC |
|---|---|
| 3 ปี | 18.2 OHSP ร้อยละเด็กกลุ่มอายุ 3 ปีมีฟันผุในฟันน้ำนม |
| 6 ปี | 18.3 OHSP ร้อยละเด็กกลุ่มอายุ 6 ปีมีฟันผุในฟันแท้ |
| 12 ปี | 18.5 OHSP ร้อยละเด็กกลุ่มอายุ 12 ปีมีฟันผุในฟันแท้ |
| 60 ปีขึ้นไป | [18.11 OHSP ร้อยละของผู้สูงอายุ ที่มีฟันแท้ใช้งานได้ไม่น้อยกว่า 20 ซี่](https://hdc.moph.go.th/cpm/public/standard-report-detail/0317b7abf99b89c45555e97e19c4cb21?subcatalogId=db30e434e30565c12fbac44958e338d5) |

ข้อมูลระดับจังหวัดที่ HDC แบ่งเป็นไฟล์ละ 100,000 รายการ ให้เก็บทุกไฟล์ โปรแกรมจะนำมาต่อกันให้เอง
แนะนำให้จัดเป็นโฟลเดอร์ `data\3ปี`, `data\6ปี`, `data\12ปี`, `data\60ปี` (โฟลเดอร์เดิมของเวอร์ชัน .exe ใช้ได้เลย)

### 3. เปิดไฟล์และเลือกข้อมูล

1. ดับเบิลคลิก `OHSP-Dashboard-vX.Y.Z.html` ให้เปิดใน **Google Chrome** หรือ **Microsoft Edge** รุ่นปัจจุบัน
2. กด **เลือกทั้งโฟลเดอร์** แล้วเลือกโฟลเดอร์ `data` หรือลากไฟล์ .xlsx มาวาง
3. ตรวจช่อง **กลุ่มอายุ** ของแต่ละไฟล์ โปรแกรมดูจากชื่อโฟลเดอร์ → ชื่อไฟล์ → คอลัมน์ age_y ในข้อมูล
   ถ้ามีป้ายสีเหลือง "ข้อมูลในไฟล์ดูเหมือน…" ให้ตรวจสอบอีกครั้ง
4. กด **สร้าง Dashboard** ข้อมูลระดับจังหวัดหลายแสนรายการใช้เวลาเพียงไม่กี่สิบวินาที

> ระวังอย่าเลือกไฟล์ที่ส่งออกซ้ำกัน (ชื่อต่างกันแต่ข้อมูลชุดเดียวกัน) เพราะจะถูกนับซ้ำ

### 4. บันทึกหรือส่งต่อรายงาน

กด **บันทึกรายงานเป็นไฟล์** ที่แถบด้านบน จะได้ไฟล์ .html ที่มีแต่ตัวเลขสรุประดับหน่วยบริการ
เปิดซ้ำได้โดยไม่ต้องเลือกไฟล์ Excel ใหม่ และส่งต่อผู้อื่นได้

### ทางเลือกสำรอง: โปรแกรม .exe

หน้า Releases ยังมีไฟล์ `OralHealthDashboard-vX.Y.Z.zip` (โปรแกรม .exe แบบเดิม) ให้ดาวน์โหลด
ผลคำนวณเหมือนกันทุกตัวเลข แต่ Windows 11 อาจบล็อก จึงแนะนำให้ใช้ไฟล์ HTML เป็นหลัก
วิธีใช้ .exe ดูในไฟล์ `อ่านก่อนใช้งาน.txt` ภายใน zip

## รายงานที่ได้

| ส่วน | เนื้อหา |
|---|---|
| การ์ดสรุป | ความครอบคลุมการตรวจฟันแยกรายกลุ่มอายุ |
| สรุปรายอำเภอ | % Caries Free และค่าเฉลี่ย dmft/DMFT ของอายุ 3, 6, 12 ปี ทุกอำเภอในตารางเดียว ไล่สีเทียบกันในคอลัมน์ ติดดาวอำเภอที่ดีที่สุด เรียงลำดับได้ |
| ตารางที่ 1 | คุณภาพของข้อมูลการตรวจ |
| ตารางที่ 2 | ร้อยละผู้ปราศจากฟันผุและมีประสบการณ์ฟันผุ |
| ตารางที่ 3 | ค่าเฉลี่ยฟันผุ ถอน อุด (ซี่ต่อคน) |
| ตารางที่ 4 | ร้อยละผู้มีเหงือกอักเสบและสภาวะปริทันต์ (อายุ 12 และ 60+) |
| ตารางที่ 5 | ค่าเฉลี่ยจำนวน sextant แต่ละสภาวะ (อายุ 12 และ 60+) |
| ตารางที่ 6 | ผู้สูงอายุที่มีฟันใช้งาน 20 ซี่ และคู่สบฟันหลัง 4 คู่ขึ้นไป |
| ตารางที่ 7 | ความจำเป็นในการรักษา |

กรองดูได้ทั้งระดับจังหวัด รายอำเภอ และรายหน่วยบริการ พร้อมปุ่มดาวน์โหลดตารางทั้งหมดเป็น CSV

ทุกตารางมี

* **เมนูซ้าย** สำหรับกระโดดไปแต่ละตาราง พร้อมไฮไลต์หัวข้อที่กำลังดู
* **ปุ่มแสดงกราฟ** เปิดกราฟแท่งพร้อมตัวเลขกำกับทุกแท่ง (วาดด้วย SVG ไม่ต้องต่ออินเทอร์เน็ต)
* **กล่องข้อสังเกต** สรุปประเด็นที่น่าสนใจจากข้อมูลโดยอัตโนมัติ เช่น กลุ่มอายุที่ตรวจได้น้อยที่สุด
  สัดส่วนฟันผุที่ยังไม่ได้รักษา และการเปรียบเทียบกับค่าเฉลี่ยจังหวัดพร้อมอันดับของอำเภอ
  ข้อสังเกตคำนวณใหม่ทุกครั้งที่เปลี่ยนตัวกรอง และจะไม่สรุปเป็นร้อยละเมื่อฐานข้อมูลน้อยกว่า 30 คน

**ปีงบประมาณ** โปรแกรมเลือกให้อัตโนมัติจากวันที่ตรวจล่าสุดในข้อมูล เช่น ถ้าล่าสุดคือ 7 ก.ค. 2569
จะวิเคราะห์ปีงบประมาณ 2569 (1 ต.ค. 2568 – 30 ก.ย. 2569) รายการที่ตรวจนอกช่วงนี้จะไม่ถูกนำมาคำนวณ

รายละเอียดเงื่อนไขการคำนวณทุกตาราง อ่านได้ที่ [`docs/เอกสารอธิบายเงื่อนไขการคำนวณ.docx`](docs/)

## ความเป็นส่วนตัวของข้อมูล

ไฟล์ Data Exchange มีเลขบัตรประชาชนและข้อมูลระบุตัวบุคคล โปรแกรมจึงออกแบบดังนี้

* ไฟล์ Excel ถูกอ่านและคำนวณ **ในเบราว์เซอร์ของเครื่องนั้น** ไม่มีการอัปโหลดไปที่ใด
* หน้าเว็บมี **Content-Security-Policy ห้ามเชื่อมต่อเครือข่ายทุกชนิด** (`connect-src 'none'`)
  ไม่โหลดไฟล์ใดจากภายนอก ใช้งานได้แม้ไม่มีอินเทอร์เน็ต ตรวจสอบได้จากโค้ดในไฟล์
* เก็บไว้ในหน่วยความจำเฉพาะคอลัมน์ผลตรวจที่ใช้คำนวณ ไม่เก็บชื่อ สกุล เลขบัตร ที่อยู่ วันเกิด
  และ **ไม่บันทึกอะไรลงเครื่อง** ปิดแท็บแล้วข้อมูลหายทั้งหมด

| ไฟล์ | มีข้อมูลส่วนบุคคลหรือไม่ |
|---|---|
| รายงานที่กด "บันทึกรายงานเป็นไฟล์" | **ไม่มี** เป็นตัวเลขสรุประดับหน่วยบริการ ส่งต่อได้ |
| CSV จากปุ่มดาวน์โหลดในรายงาน | **ไม่มี** เป็นตารางสรุป |
| ไฟล์ Excel จาก HDC | **มี** ข้อมูลรายบุคคลครบ เก็บไว้ในเครื่องเท่านั้น |

**ห้าม** นำไฟล์ Excel จาก HDC หรือโฟลเดอร์ `data` ขึ้น GitHub หรือที่แชร์สาธารณะ
ไฟล์ `.gitignore` และ `packaging/check_safe.py` ของโครงการกันไว้ให้แล้ว

## ตัวเลือกเพิ่มเติมของโปรแกรม .exe (ไม่จำเป็นสำหรับการใช้งานปกติ)

เปิด Command Prompt ในโฟลเดอร์ที่วางโปรแกรม แล้วพิมพ์

```
OralHealthDashboard.exe --force              ประมวลผลไฟล์ Excel ใหม่ทั้งหมด
OralHealthDashboard.exe --full-csv           เก็บทุกคอลัมน์ลง combined.csv รวมข้อมูลส่วนบุคคล
OralHealthDashboard.exe --no-open            ไม่ต้องเปิดเบราว์เซอร์เมื่อเสร็จ
OralHealthDashboard.exe --no-update-check    ไม่ต้องตรวจสอบเวอร์ชันใหม่
```

ปกติโปรแกรมจะข้ามการอ่าน Excel ซ้ำถ้าไฟล์ไม่เปลี่ยนแปลง ทำให้เปิดครั้งต่อไปเร็วขึ้นมาก
ถ้าต้องการบังคับให้อ่านใหม่ ใช้ `--force` หรือลบไฟล์ `ผลลัพธ์\combined.csv`

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| ขึ้นว่าเบราว์เซอร์เก่าเกินไป | ใช้ Chrome หรือ Edge รุ่นปัจจุบัน (หรือ Firefox 113 ขึ้นไป) |

| ไฟล์ขึ้น ✗ ไม่ใช่ไฟล์ Excel (.xlsx) | ไฟล์เสียหายหรือเป็น .xls/.csv ให้ส่งออกจาก HDC ใหม่เป็น .xlsx |

| เครื่องช้ามากหรือแท็บค้าง | เครื่องแรมน้อย ปิดโปรแกรมอื่นก่อน หรือแยกทำทีละกลุ่มอายุ |

โปรแกรม .exe แจ้งสาเหตุเป็นภาษาไทยบนหน้าจอ และบันทึกไว้ใน `ผลลัพธ์\log.txt`

## สำหรับผู้พัฒนา

### โครงสร้างโครงการ

```
src/webapp/core.js             อ่าน .xlsx (ไม่ใช้ไลบรารี) + คำนวณตาราง 1–7 ทำงานใน Web Worker
src/webapp/app.js              หน้าเลือกไฟล์และแสดง dashboard
src/webapp/shell.html          หน้าตาเว็บแอป + Content-Security-Policy
src/build_dashboard.py         เวอร์ชัน Python (.exe) และต้นแบบสูตรคำนวณ เก็บ VERSION
src/dashboard_template.html    แม่แบบหน้า dashboard ใช้ร่วมกันทั้งสองเวอร์ชัน (จุด /*__DATA__*/null คือที่ฝังข้อมูล)
src/hospitals.csv              ตารางเทียบรหัสหน่วยบริการกับอำเภอ/จังหวัด (เข้ารหัส cp874)
tools/build_webapp.py          ประกอบ dist/OHSP-Dashboard.html
tools/parity_test.mjs          ตรวจว่าเวอร์ชันเว็บคำนวณตรงกับเวอร์ชัน Python ทุกค่า
tools/make_sample_data.py      สร้างข้อมูลจำลองสำหรับทดสอบ
packaging/                     ประกอบ zip ของ .exe, ตรวจไฟล์ก่อน push, release notes
docs/                          เอกสารอธิบายเงื่อนไขการคำนวณและแผนงาน
```

### สร้างไฟล์ HTML

```bash
pip install openpyxl
python tools/build_webapp.py                 # ได้ dist/OHSP-Dashboard.html
```

ถ้าแก้สูตรคำนวณ ต้องแก้ทั้ง `src/build_dashboard.py` และ `src/webapp/core.js` แล้วทดสอบว่าตรงกัน

```bash
python tools/make_sample_data.py data
python src/build_dashboard.py --no-open --no-update-check
node tools/parity_test.mjs data ผลลัพธ์/summary.json dist/hospitals.packed.json
```

GitHub Actions รันการทดสอบนี้ทุกครั้งที่ปล่อยเวอร์ชัน ถ้าไม่ตรงกันจะไม่ปล่อย Release

### รันด้วย Python

```bash
pip install openpyxl
python src/build_dashboard.py
```

### สร้างไฟล์ .exe

บนเครื่อง Windows

```
build.bat
```

หรือให้ GitHub สร้างให้อัตโนมัติ โดยติด tag แล้ว push

```bash
git tag v1.0.0
git push origin v1.0.0
```

GitHub Actions จะสร้างไฟล์ HTML (พร้อมทดสอบ) และ .exe บน Windows แล้วแนบทั้งสองไฟล์ไว้ในหน้า Releases ให้เอง

### ปล่อยเวอร์ชันใหม่

1. แก้โค้ดให้เรียบร้อย
2. เปลี่ยนเลข `VERSION` ใน `src/build_dashboard.py` เช่นจาก `2.0.0` เป็น `2.1.0` (ไฟล์ HTML ใช้เลขเดียวกัน)
3. ดับเบิลคลิก `release.bat` (commit + push + tag) หรือ `git commit` แล้ว `git tag v2.1.0 && git push origin main --tags`

ชื่อ repository สำหรับการแจ้งเตือนเวอร์ชันใหม่ ระบบเติมให้อัตโนมัติตอน build
(workflow ใช้ค่าจาก GitHub ส่วน `build.bat` อ่านจาก `git remote`)
ถ้าต้องการกำหนดเอง ใช้ `python packaging/set_repo.py owner/repo`

เลขเวอร์ชันใช้แบบ `major.minor.patch` และเปรียบเทียบทีละส่วน ดังนั้น `1.10.0` ใหม่กว่า `1.2.0`

สำหรับ .exe ผู้ใช้ปลายทางวางไฟล์ `hospitals.csv` ไว้ข้าง ๆ ไฟล์ .exe ได้ โปรแกรมจะใช้ไฟล์นั้นแทนของที่ฝังมา
สำหรับไฟล์ HTML ต้อง build ใหม่ (`tools/build_webapp.py`)
