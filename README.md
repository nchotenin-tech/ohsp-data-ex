# Dashboard วิเคราะห์สภาวะช่องปาก (HDC Data Exchange)

โปรแกรมสำหรับหน่วยบริการและสำนักงานสาธารณสุข ใช้แปลงไฟล์ Excel ที่ส่งออกจากระบบ HDC
(Data Exchange การตรวจฟัน) ให้เป็นรายงานสรุปสภาวะช่องปากกลุ่มอายุ 3, 6, 12 ปี และ 60 ปีขึ้นไป
ตามแบบตารางที่ 1–7 ของกรมอนามัย

ทำงานบนเครื่องของท่านเองทั้งหมด ไม่มีการส่งข้อมูลออกนอกเครื่อง

---

## วิธีใช้งาน (สำหรับพื้นที่)

### 1. ดาวน์โหลด

ไปที่หน้า **Releases** ของโครงการนี้ แล้วดาวน์โหลดไฟล์ `OralHealthDashboard-vX.Y.Z.zip`
จากนั้นคลิกขวาที่ไฟล์ zip เลือก **Extract All** แตกไฟล์ไว้ที่ไหนก็ได้ เช่น `D:\Dashboardช่องปาก\`

### 2. เปิดโปรแกรมครั้งแรก

ดับเบิลคลิก `OralHealthDashboard.exe` โปรแกรมจะสร้างโฟลเดอร์ให้อัตโนมัติแล้วปิดตัวเอง

```
Dashboardช่องปาก\
├── OralHealthDashboard.exe
├── data\
│   ├── 3ปี\      ← โปรแกรมสร้างให้
│   ├── 6ปี\
│   ├── 12ปี\
│   └── 60ปี\
└── ผลลัพธ์\
```

> **Windows แจ้งเตือน "Windows protected your PC"**
> เกิดขึ้นกับโปรแกรมที่ยังไม่ได้ซื้อใบรับรองดิจิทัลทุกตัว
> ให้กด **More info** แล้วกด **Run anyway** ครั้งแรกครั้งเดียว

### 3. นำข้อมูลของท่านมาใส่

ส่งออกข้อมูลจาก HDC เมนู Data Exchange การตรวจฟัน แล้วนำไฟล์ `.xlsx` มาวางในโฟลเดอร์ตามกลุ่มอายุ

* วางได้มากกว่าหนึ่งไฟล์ต่อโฟลเดอร์ โปรแกรมจะนำมาต่อกันให้เอง
  (ข้อมูลระดับจังหวัดที่ HDC แบ่งส่งออกทีละ 100,000 รายการ วางทุกไฟล์ได้เลย)
* ปิดไฟล์ใน Excel ให้เรียบร้อยก่อนเปิดโปรแกรม
* ไม่ต้องแก้ไขหัวตารางหรือชื่อไฟล์

### 4. ดับเบิลคลิกโปรแกรมอีกครั้ง

หน้าจอจะแสดงความคืบหน้า ใช้เวลาประมาณ 1–3 นาทีสำหรับข้อมูลระดับจังหวัด
เมื่อเสร็จ เบราว์เซอร์จะเปิดรายงานขึ้นมาเอง

ผลลัพธ์อยู่ที่ `ผลลัพธ์\dashboard.html` เปิดซ้ำเมื่อไรก็ได้ และส่งต่อให้ผู้อื่นได้ (ดูหัวข้อความเป็นส่วนตัว)

## รายงานที่ได้

| ส่วน | เนื้อหา |
|---|---|
| การ์ดสรุป | ความครอบคลุมการตรวจฟันแยกรายกลุ่มอายุ |
| ตารางที่ 1 | คุณภาพของข้อมูลการตรวจ |
| ตารางที่ 2 | ร้อยละผู้ปราศจากฟันผุและมีประสบการณ์ฟันผุ |
| ตารางที่ 3 | ค่าเฉลี่ยฟันผุ ถอน อุด (ซี่ต่อคน) |
| ตารางที่ 4 | ร้อยละผู้มีเหงือกอักเสบและสภาวะปริทันต์ (อายุ 12 และ 60+) |
| ตารางที่ 5 | ค่าเฉลี่ยจำนวน sextant แต่ละสภาวะ (อายุ 12 และ 60+) |
| ตารางที่ 6 | ผู้สูงอายุที่มีฟันใช้งาน 20 ซี่ และคู่สบฟันหลัง 4 คู่ขึ้นไป |
| ตารางที่ 7 | ความจำเป็นในการรักษา |

กรองดูได้ทั้งระดับจังหวัด รายอำเภอ และรายหน่วยบริการ พร้อมปุ่มดาวน์โหลดตารางทั้งหมดเป็น CSV

**ปีงบประมาณ** โปรแกรมเลือกให้อัตโนมัติจากวันที่ตรวจล่าสุดในข้อมูล เช่น ถ้าล่าสุดคือ 7 ก.ค. 2569
จะวิเคราะห์ปีงบประมาณ 2569 (1 ต.ค. 2568 – 30 ก.ย. 2569) รายการที่ตรวจนอกช่วงนี้จะไม่ถูกนำมาคำนวณ

รายละเอียดเงื่อนไขการคำนวณทุกตาราง อ่านได้ที่ [`docs/เอกสารอธิบายเงื่อนไขการคำนวณ.docx`](docs/)

## ความเป็นส่วนตัวของข้อมูล

| ไฟล์ | มีข้อมูลส่วนบุคคลหรือไม่ |
|---|---|
| `ผลลัพธ์\dashboard.html` | **ไม่มี** เป็นตัวเลขสรุประดับหน่วยบริการเท่านั้น ส่งต่อได้ปลอดภัย |
| `ผลลัพธ์\combined.csv` | ตัด ชื่อ สกุล เลขบัตรประชาชน ที่อยู่ และวันเกิด ออกให้แล้ว |
| `data\*.xlsx` | **มี** ข้อมูลรายบุคคลครบ เก็บไว้ในเครื่องเท่านั้น |

ถ้าจำเป็นต้องตรวจสอบรายคน เปิดโปรแกรมด้วยตัวเลือก `--full-csv` จะได้ไฟล์ที่มีทุกคอลัมน์
(ดูหัวข้อตัวเลือกเพิ่มเติม)

**ห้าม** นำโฟลเดอร์ `data` หรือไฟล์ `combined.csv` ขึ้น GitHub หรือที่แชร์สาธารณะ
ไฟล์ `.gitignore` ของโครงการกันไว้ให้แล้ว

## การอัปเดต

### อัปเดตข้อมูลของพื้นที่

วางไฟล์ Excel ชุดใหม่ทับของเดิมในโฟลเดอร์ `data` แล้วเปิดโปรแกรมอีกครั้ง
โปรแกรมดูวันที่แก้ไขไฟล์เอง ถ้าเปลี่ยนจะอ่านใหม่ให้อัตโนมัติ
ปีงบประมาณก็จะเลื่อนตามวันที่ตรวจล่าสุดในข้อมูลชุดใหม่เอง

### อัปเดตตัวโปรแกรม

โปรแกรมจะตรวจสอบเวอร์ชันล่าสุดจาก GitHub ให้ตอนเปิด ใช้เวลาไม่เกิน 3 วินาที
ถ้าไม่มีอินเทอร์เน็ตหรือถูกไฟร์วอลล์กั้นจะข้ามไปเงียบ ๆ ไม่กระทบการทำงาน
การตรวจสอบนี้เป็นการถามเลขเวอร์ชันเท่านั้น **ไม่มีการส่งข้อมูลใด ๆ ของพื้นที่ออกไป**
ปิดได้ด้วยตัวเลือก `--no-update-check`

เมื่อมีเวอร์ชันใหม่ ให้ดาวน์โหลดไฟล์ zip แล้วนำ `OralHealthDashboard.exe` ตัวใหม่มาวางทับตัวเดิม
โฟลเดอร์ `data` และ `ผลลัพธ์` ยังอยู่ครบเหมือนเดิม ไม่ต้องตั้งค่าอะไรใหม่

หลังอัปเดตโปรแกรม การประมวลผลรอบแรกจะอ่านไฟล์ Excel ใหม่ทั้งหมดหนึ่งครั้งโดยอัตโนมัติ
เพื่อให้แน่ใจว่าผลลัพธ์ตรงกับสูตรคำนวณของเวอร์ชันใหม่ รอบถัดไปจะกลับมาเร็วเหมือนเดิม

## ตัวเลือกเพิ่มเติม (ไม่จำเป็นสำหรับการใช้งานปกติ)

เปิด Command Prompt ในโฟลเดอร์ที่วางโปรแกรม แล้วพิมพ์

```
OralHealthDashboard.exe --force              ประมวลผลไฟล์ Excel ใหม่ทั้งหมด
OralHealthDashboard.exe --full-csv           เก็บทุกคอลัมน์ลง combined.csv รวมข้อมูลส่วนบุคคล
OralHealthDashboard.exe --no-open            ไม่ต้องเปิดเบราว์เซอร์เมื่อเสร็จ
OralHealthDashboard.exe --no-update-check    ไม่ต้องตรวจสอบเวอร์ชันใหม่
```

ปกติโปรแกรมจะข้ามการอ่าน Excel ซ้ำถ้าไฟล์ไม่เปลี่ยนแปลง ทำให้เปิดครั้งต่อไปเร็วขึ้นมาก
ถ้าต้องการบังคับให้อ่านใหม่ ใช้ `--force` หรือลบไฟล์ `ผลลัพธ์\combined.csv`

## เมื่อเกิดปัญหา

โปรแกรมจะแจ้งสาเหตุเป็นภาษาไทยบนหน้าจอ และบันทึกไว้ในไฟล์ `ผลลัพธ์\log.txt`
ถ้าแก้เองไม่ได้ กรุณาแจ้งปัญหาที่หน้า Issues พร้อมแนบไฟล์ `log.txt`

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| แจ้งว่าไม่พบไฟล์ Excel | ยังไม่ได้วางไฟล์ หรือวางผิดโฟลเดอร์ |
| แจ้งว่าไม่มีคอลัมน์ที่จำเป็น | ไฟล์ไม่ได้ส่งออกจากเมนู Data Exchange การตรวจฟัน หรือหัวตารางถูกแก้ไข |
| แจ้งว่าเขียนไฟล์ไม่ได้ | เปิด `dashboard.html` หรือ `combined.csv` ค้างไว้ ให้ปิดก่อน |
| ข้ามไฟล์ที่ขึ้นต้นด้วย `~$` | ไฟล์ชั่วคราวจากการเปิด Excel ค้างไว้ ไม่ใช่ความผิดพลาด |
| หน้าจอมีตัวอักษรเพี้ยน | Command Prompt รุ่นเก่า ไม่กระทบผลลัพธ์ ดูข้อความเต็มได้ใน `log.txt` |

## สำหรับผู้พัฒนา

### รันด้วย Python

```bash
pip install openpyxl
python build_dashboard.py
```

### โครงสร้างโครงการ

```
src/build_dashboard.py         โค้ดหลัก อ่าน Excel คำนวณ และสร้างรายงาน
src/dashboard_template.html    แม่แบบหน้าเว็บ (จุด /*__DATA__*/null คือที่ฝังข้อมูล)
src/hospitals.csv              ตารางเทียบรหัสหน่วยบริการกับอำเภอ/จังหวัด (เข้ารหัส cp874)
tools/                         สคริปต์เสริม เช่น สร้างเอกสารและข้อมูลตัวอย่าง
packaging/make_package.py      ประกอบไฟล์ zip สำหรับแจกจ่าย
docs/                          เอกสารอธิบายเงื่อนไขการคำนวณและแผนงาน
```

### สร้างไฟล์ .exe

บนเครื่อง Windows

```
build.bat
```

หรือให้ GitHub สร้างให้อัตโนมัติ โดยติด tag แล้ว push

```bash
git tag v1.0.0
git push origin v1.0.0
```

GitHub Actions จะ build บน Windows แล้วแนบไฟล์ zip ไว้ในหน้า Releases ให้เอง

### ปล่อยเวอร์ชันใหม่

1. แก้โค้ดให้เรียบร้อย
2. เปลี่ยนเลข `VERSION` ใน `src/build_dashboard.py` เช่นจาก `1.0.0` เป็น `1.1.0`
3. `git commit` แล้ว `git tag v1.1.0 && git push origin main --tags`

ชื่อ repository สำหรับการแจ้งเตือนเวอร์ชันใหม่ ระบบเติมให้อัตโนมัติตอน build
(workflow ใช้ค่าจาก GitHub ส่วน `build.bat` อ่านจาก `git remote`)
ถ้าต้องการกำหนดเอง ใช้ `python packaging/set_repo.py owner/repo`

เลขเวอร์ชันใช้แบบ `major.minor.patch` และเปรียบเทียบทีละส่วน ดังนั้น `1.10.0` ใหม่กว่า `1.2.0`

### อัปเดตตาราง hospitals.csv

ถ้ามีหน่วยบริการใหม่ ให้แทนที่ `src/hospitals.csv` แล้ว build ใหม่
หรือผู้ใช้ปลายทางวางไฟล์ `hospitals.csv` ไว้ข้าง ๆ ไฟล์ .exe โปรแกรมจะใช้ไฟล์นั้นแทนของที่ฝังมา
